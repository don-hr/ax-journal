AIドキュメントをURLで共有する——BASE「pon」が変えた社内情報流通

AIコーディングが浸透するにつれ、組織内に「流通するが読まれない」ドキュメントが急増している。BASE社のCTO川口氏が2026年6月に公開したブログ記事は、その問題への根本的な答えを提示した——AIが生成したHTMLをそのまま社内ホストし、「URLで共有する」を組織の標準にする、という設計思想だ。

AIコーディングが生んだ「読めるのに読まれない」ドキュメント問題

AIコーディングツールの普及により、実装計画・設計メモ・技術仕様書が以前の何倍もの速さで生成されるようになった。しかしBASE社CTOの川口氏（id:dmnlk）が直面した問題は逆説的だった。「ドキュメントは増えるが、人間が読むのに適さない」という状況だ。

マークダウン形式で共有されるAI生成ドキュメントは、長く、構造はあるが、チャットツールに貼り付けると見た目がくずれ、Notionに移すとレイアウトの自由度が失われる。AIが「読みやすく」設計したHTMLが、変換を経るたびに「読みにくい」ものへと劣化する。これは小さな摩擦のように見えて、実際には「誰も読まないドキュメント」を組織全体で量産する構造的な問題だ。

AX Journal 編集部の視点

「AIが生成したドキュメントを人間が読める形に変換する」という問いの立て方自体が間違っている。正しい問いは「フォーマット変換ゼロで配布できる形式で、最初から生成させる」ことだ。ponはその設計思想を体現したインフラである。

NotionではなくHTMLを選んだ理由——「変換を挟まない」という設計思想

川口氏が選んだ解決策は、Notionへの移行でも、マークダウンビューアの導入でもなかった。AIが生成したHTMLをそのまま社内でホストできる環境を作るという、シンプルかつ根本的な方針への転換だ。

Notionにはレイアウトの自由度という制約がある。AIが精密に設計した表や構造も、Notionのブロック体系に合わせた変換を挟んだ瞬間に情報の一部が失われる。HTMLであれば、AIが出力したそのままを即座にURLとして配布できる。「変換を挟まない素直さ」——これがHTMLを選んだ核心的な理由だ。

図1｜Notion vs 社内HTMLホスティング（pon方式）比較
比較軸 Notion 社内HTMLホスティング（pon）
AI生成物の扱い ブロックへの変換が必要、レイアウト劣化あり 変換ゼロ でそのまま配信
共有方法 ページ権限設定 + URLシェア URLで即共有（IAP認証込み）
レイアウト自由度 Notionブロック制約あり HTMLフルコントロール
対象ユーザー 全社（書く側・読む側ともにNotion慣れが必要） 書く側はAI任せ、読む側はURLだけ
運用コスト 月額課金、管理者が必要 GCS + Cloud Run（使量課金・軽量）

「pon」の3層構成——GCS・Cloud Run・IAPで作る社内URLインフラ

サービス名は「pon」。技術スタックは意図的にシンプルに設計されている。Google Cloud Storageでファイルを保管し、Cloud Runでフルマネージドに配信し、Identity-Aware ProxyでGoogle Workspaceと連携した認証を担う。この3層構成がすべてだ。

図2｜「pon」の技術スタック3層
Layer 1 / 保管 GCS Google Cloud Storage
ファイルをオブジェクトとして保持
Layer 2 / 配信 Cloud Run フルマネージド配信
スケーリング不要・コストゼロから
Layer 3 / 認証 IAP Identity-Aware Proxy
Google Workspace連携で社内限定

追加で実装された運用施策も重要だ。自動7日削除（古いドキュメントの自然消滅）、CI統合（ビルド成果物を自動でponにアップ）、Claude Code連携（AIが生成した出力を直接ponにプッシュ）。これらが「AIが作ってURLで渡す」という一連の流れをノーコードで完成させた。

エンジニアから全社へ——「pon」が生んだ情報流通の文化変容

「pon」のユースケースは当初、エンジニアによる実装計画の共有に限定されていた。しかし変化は予想外の方向から生まれた。財務・経理など非エンジニア部門が「資料をHTMLにして共有する」習慣を自発的に取り入れ始めたのだ。

社内デフォルトが「読みやすい1ページをURLで共有する」に変わった。「pon」というサービス名が動詞として使われるほど文化に根付いた。これは技術ツールの導入ではない。AIドキュメントをチャットに貼るのではなく、URLで渡す——という情報流通の様式そのものが変わった事例だ。

「変換を挟まない素直さ」がHTMLの強みでした。——川口CTO（BASE株式会社）

まとめ

AI生成ドキュメントの問題は、ドキュメントの「質」ではなく「流通経路」にある。ponが示した解答は、フォーマット変換ゼロ・URLで共有・社内認証の3点セットで情報流通インフラを作り直すことだった。人事・HR部門でも、JD・組織設計案・評価基準書といった「AIで下書きする書類」が急増している。同様の仕組みは即座に応用できる。

  • 社内でAI生成ドキュメントが増えているなら、まず「どのフォーマットで共有しているか」を棚卸しし、変換ステップの数を数える
  • HTMLホスティング環境はGoogle Cloud Storage + Cloud Run + IAPというシンプルな構成で実現できる。自社エンジニアへの導入提案材料として活用できる
  • 「URL共有」を社内標準にするには、まずエンジニア部門で小さく始め、他部門への波及を自然に待つ設計が有効——ponはその好例だ
